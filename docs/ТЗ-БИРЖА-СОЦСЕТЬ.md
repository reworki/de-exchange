## 1. Позиционирование

DE — не просто биржа, а биржа-соцсеть: у каждого игрока есть **ник, профиль и публичная
статистика**. Другие игроки **подписываются**, смотрят ленту успехов и топ.

Ключевая мысль: профиль — это витрина капитала. Подписка = «интересно, как он торгует».
Никаких лайков и комментариев на старте: только подписки, цифры и события.

Экраны, которые появляются:

```
[ 📈 Биржа ] [ 💼 Портфель ] [ 🏰 Активы ] [ 🎁 Кейсы ] [ 🛒 Маркет ]
[ 🏦 Банк ] [ 💸 Перевести ] [ 🔢 Номера ] [ 👤 Профиль ] [ 🌐 Лента ] [ 🏆 Топ ]
```

## 2. Аккаунт и ник

Почта из регистрации убирается. Вход и регистрация — по нику.

```
НИК            [ knote6037        ]   ✓ свободен
ПАРОЛЬ         [ ••••••••        ]
ПОВТОР ПАРОЛЯ  [ ••••••••        ]
                [ СОЗДАТЬ АККАУНТ ]
```

Правила ника:

| Правило | Значение |
|---|---|
| Длина | 3–16 символов |
| Разрешено | `a-z а-я ё 0-9 _ -`, регистр любой |
| Первый символ | буква или цифра |
| Уникальность | без учёта регистра: `KNOTE` = `knote` |
| Хранится | как ввёл игрок |
| Только цифры | можно, кроме 8 цифр подряд (это кошелёк) |
| Зарезервировано | `admin`, `root`, `system`, `support`, `de`, `exchange`, `bot`, `api`, `test`, `mod`, `owner`, `вася`, `кент` |

```js
const NICK_RE = /^[a-zа-яё0-9][a-zа-яё0-9_-]{2,15}$/i;
const normNick = (s) => String(s || '').trim().toLowerCase();
```

Аккаунт в Blobs (ключ объекта = `nick_lc`):

```js
{
  nick: "knote6037", nick_lc: "knote6037",
  pass: "<хеш пароля скрыт>", wallet: "55555555", admin: true,
  created: 1794000000000, updated: 1795000000000, last_seen: 1795000000000,
  bio: "президент СШН", avatar: { emoji: "🐺", color: "#c0561b" },
  privacy: { hideBalance: false, private: false },
  rec: "h2…",                    // хеш кода восстановления
  legacy_email: "…",             // только у мигрированных
  social: { followers: 0, following: 0 },
  snap: { d1: 1.482e15, d7: 1.31e15, t: 1795000000000 },   // снимки капитала
  state: { ex, nft, ext, led }
}
```

Аватар на старте — эмодзи + цвет фона (12 эмодзи, 8 цветов, выбираются в профиле).
Загрузка картинок — не в этой версии.

## 3. Профиль

Публичная карточка `/профиль/@ник`:

```
┌──────────────────────────────────────────────┐
│  🐺  @knote6037            [✓ подписан]      │
│      президент СШН · на бирже с 12.03.2026    │
│      кошелёк 55555555                         │
│                                              │
│  КАПИТАЛ        $579.63T    ▲ +11% за 7 дней │
│  ПОДПИСЧИКИ     1 284       ПОДПИСОК: 12     │
│  СДЕЛОК         52          NFT: 9           │
│  МЕСТО В ТОПЕ   #2 из 148                     │
├──────────────────────────────────────────────┤
│  Портфель: KNT 55%, BTC 20%, ETH 9% …        │
│  Последние события (лента)                    │
└──────────────────────────────────────────────┘
```

Свои поля редактируются в панели аккаунта: ник (раз в 7 дней), био (до 120 символов),
аватар. Чужие поля не редактируются никак.

## 4. Подписки

- Однонаправленные, как в соцсетях: я подписан на него ≠ он на меня.
- Нельзя подписаться на себя (`400 self`).
- Кнопка «Подписаться» / «✓ Подписан» (повторный клик — отписка).
- Счётчики `social.followers` / `social.following` пересчитываются на сервере, не на клиенте.
- Списки: `GET /api/followers?nick=` и `GET /api/following?nick=` — карточки по 20 штук,
  постранично (`?offset=`).
- Лимиты: 500 подписок на аккаунт, 60 действий в минуту (анти-спам).
- Уведомлений на старте нет: новые подписчики видны в ленте профиля.
- Закрытый профиль (`privacy.private`) — в топе и поиске не показывается, подписка
  отправляет заявку (`pending`), владелец принимает в разделе «Заявки».

Хранение связей: отдельный объект `edges` в Blobs
`{ "knote6037>vasya": 1795000000000, … }` — ключ `from>to`, значение время.
Обратный индекс (`to>from`) не нужен: подписчики получаются сканом по префиксу или
через `social` счётчики + отдельный объект `followers:<nick>` со списком. Рекомендация:
`edges` + `followers:<nick>` (массив `from`), чтобы не сканировать всё.

## 5. Статистика

Считает **сервер** из `acc.state.ex` на каждом `POST /api/state` и при `GET /api/profile`
(если кэш старше 60 секунд). Клиент только отображает.

| Метрика | Формула |
|---|---|
| Капитал | `ex.usdt + Σ(amounts[k] × цена[k])`, цены — из таблицы сервера |
| 24ч / 7д | `капитал` против `snap.d1` / `snap.d7`, в % и деньгах |
| Сделки | `ex.trades.length` (и объём `Σ total` за 7 дней) |
| NFT | `nft.items.length` |
| Переводы | из `led`: получено / отправлено за 30 дней |
| Подписчики | `social.followers` |
| Место в топе | позиция в рейтинге по капиталу среди видимых профилей |
| Уровень | по капиталу: 1 — до $1M, 2 — $1M, 3 — $1B, 4 — $1T, 5 — $100T, 6 — $1Q+ |

Цены на сервере: сейчас их знает только клиент (`DEFS` в `index.html`). Нужен
`netlify/functions/prices.js` с тем же набором `{key, price}` и синхронизация руками
(при изменении `DEFS` — обновить файл). Иначе капитал на сервере будет считаться по
устаревшим ценам, и топ разъедется с профилем.

Снимки: `snap.d1` обновляется раз в час (`d1 = капитал, t = now`), `snap.d7` — раз в сутки
хранит значение недельной давности; на старте можно заполнять лениво (нет данных → «—»).

## 6. Лента

Два вида:

**Лента профиля** — последние 30 событий игрока:
`перевод получен`, `перевод отправлен`, `получен NFT`, `новая веха капитала`
(`перешёл $1B`), `смена ника`, `подписка`. Плюс сделки из `ex.trades` с пометкой
«по данным игрока» (сделки пока не проверяются сервером, §12).

**Общая лента** — последние 50 событий по всем игрокам, только серверные:
переводы, NFT, вехи, новые подписки, регистрации.

Хранение: `feed` (массив, не больше 500 записей, обрезка при записи) и `feed:<nick>`
(последние 30). Запись события — одна функция `pushEvent(nick, type, payload)`.

```js
{ id: "e1795…-12", t: 1795000000000, nick: "knote6037", lc: "knote6037",
  type: "transfer_in", text: "получил 250 USDT от @vasya", money: 250, sym: "USDT" }
```

## 7. Топ и рейтинги

Вкладка «Топ»:

- три переключателя: **по капиталу**, **по подписчикам**, **по сделкам за 7 дней**;
- таблица 100 строк: место, аватар, `@ник`, капитал, подписчики, изменение за 7 дней;
- своя строка закреплена снизу, даже если место 148-е;
- скрытые профили (`privacy.private`) и скрытый баланс (`privacy.hideBalance`) в топ
  не попадают (или показываются с «—» и без места);
- кэш топа — 60 секунд в памяти функции, чтобы не пересчитывать на каждый заход.

## 8. Приватность

Два переключателя в панели аккаунта:

1. **Скрыть капитал** — в профиле и топе вместо суммы «скрыто», место в топе не
   показывается, подписчики/сделки остаются.
2. **Закрытый профиль** — карточка видна только подписчикам; в топе и поиске не
   участвует; подписка = заявка.

## 11. Миграция старых аккаунтов

Скрипт `migrate-nicks.js`, запуск `POST /api/admin/migrate` с паролем владельца.
Перед запуском — скачать снапшот `accounts` в файл.

1. `nick = local-part(email)`, вырезать всё кроме `[a-zа-яё0-9_-]`, обрезать до 16,
   пусто → `user`.
2. Точка → `_`: `kent.vasya@rework.mail` → `kent_vasya`.
3. Не проходит `NICK_RE` (`5@gmail.com` → `5`) — оставить, правило первого символа
   только для новых (`legacy:true`).
4. Коллизия — суффикс `_2`, `_3`.
5. `legacy_email` записать, объект переложить под `nick_lc`, старый ключ удалить.
6. **Кошелёк не трогать** — иначе переводы по старым номерам уйдут в никуда.
7. `social`, `snap`, `feed` — нули, заполняются по мере работы.
8. Отчёт: таблица `email → nick → wallet`, сколько перенесено.

Клиент при первом входе по почте: получил `acc.nick` → перезаписал запись, переименовал
ключи localStorage (`__<email>` → `__<nick_lc>`), перезагрузился.

Ожидаемо на текущей базе: `knote6037@gmail.com` → `knote6037`, `kent.vasya@rework.mail`
→ `kent_vasya`, `std@c++.com` → `std`, `5@gmail.com` → `5` (legacy).

## 12. Честность цифр (важно)

Сейчас балансы приходят **с клиента**: `POST /api/state` присылает весь блоб, сервер его
сохраняет. Значит капитал в профиле и топе можно нарисовать любым.

Что делаем в этой версии:
- в профиле у блока «Сделки» пометка «по данным игрока»;
- в топ попадают все, но рядом с капиталом значок `~`, если за 7 дней не было ни одной
  серверной операции (перевода или подарка NFT) — такие цифры не подтверждены;
- честная проверка балансов — отдельная задача: серверный учёт сделок (`POST /api/trade`
  вместо клиентского пересчёта) и серверная выдача стартового капитала.

Не пытаться «починить» это на клиенте: любые проверки в браузере обходятся.

## 13. Критерии приёмки

1. Регистрация по нику: `knote_test`, ключ `knote_test`, кошелёк 8 цифр, аватар по умолчанию.
2. Тот же ник в другом регистре → `409`, форма пишет «занят» и предлагает `knote_test_2`.
3. Вход по нику и по старой почте; после входа по почте ники и данные на месте.
4. Профиль показывает капитал, подписчиков, сделки, NFT, место в топе, уровень.
5. Подписка/отписка меняет счётчики у обоих, третий клик не дублирует (`409`).
6. Списки подписчиков и подписок постранично, по 20.
7. Лента профиля: после перевода на 250 USDT появляется событие у обоих.
8. Топ: три сортировки, своя строка закреплена, скрытые профили отсутствуют.
9. Скрытый капитал: в профиле «скрыто», в топе нет места.
10. Закрытый профиль: чужой видит «профиль закрыт», подписка создаёт заявку.
11. Смена ника: данные целы, ключи localStorage переехали, старый ник свободен.
12. Консоль чистая, все 11 вкладок открываются, бейдж `⚡ v3.0 · соцсеть`.

## 15. Риски

| Риск | Что делаем |
|---|---|
| Топ накручивают клиентским state | пометка `~`, §12, серверный учёт — отдельной задачей |
| Цены на сервере разъедутся с клиентом | один файл `prices.js`, обновлять вместе с `DEFS` |

| Разрастание `feed` в Blobs | обрезка: общая 500, профильная 30 |
